Sampai pelajaran 03, `ProductService` masih tipis: tiap method hanya meneruskan satu baris Eloquent. Wajar kalau kamu bertanya, "Untuk apa service kalau isinya cuma itu?" Pelajaran bonus ini menjawabnya dengan dua fitur yang memang punya aturan bisnis:

- **Slug unik.** Produk "Kopi Susu" mendapat slug `kopi-susu`; produk kedua dengan nama sama mendapat `kopi-susu-2`.
- **Gambar produk.** Gambar disimpan di disk `public`, diganti saat edit, dan ikut dihapus saat produk dihapus.

Kedua aturan itu ditaruh di `ProductService`. Controller tetap tipis, dan aturan yang sama otomatis berlaku kalau nanti produk dibuat dari Artisan command atau API.

Titik awal pelajaran ini adalah kode akhir pelajaran 03: `ProductService` dari pelajaran 02 dan `ProductController` tipis dari pelajaran 03.

## Langkah 1 — Petakan siapa mengerjakan apa

| Lapisan | Tugas di fitur ini | Tidak boleh |
|---|---|---|
| Form Request | Validasi file: harus gambar, maksimal 2 MB | Menyimpan file |
| Controller | Memisahkan data teks dan file dari request, lalu memanggil service | Membuat slug atau menyentuh `Storage` |
| Service | Membuat slug unik, menyimpan dan menghapus gambar | Menerima object `Request`, mengembalikan `redirect()` atau `view()` |
| Model | Mengizinkan kolom `slug` dan `image` diisi massal | Logic bisnis |

Aturan yang sama seperti pelajaran 02: **service menerima data biasa**. Data teks dikirim sebagai `array`, gambar dikirim sebagai `UploadedFile` (atau `null` kalau tidak ada).

## Langkah 2 — Tambah kolom `slug` dan `image`

Tabel `products` sudah berisi data, jadi kita tidak mengubah migration lama. Buat migration baru yang menambah kolom:

```bash
php artisan make:migration add_slug_and_image_to_products_table --table=products
```

Kolom `slug` dibuat `nullable()` karena produk lama belum punya slug. Kalau dibuat wajib, SQLite menolak menambah kolom `NOT NULL` tanpa nilai default ke tabel yang sudah berisi data. Produk lama akan mendapat slug saat diedit (lihat Langkah 5).

Here's your complete `database/migrations/xxxx_xx_xx_xxxxxx_add_slug_and_image_to_products_table.php`:

```php title="database/migrations/xxxx_xx_xx_xxxxxx_add_slug_and_image_to_products_table.php"
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::table('products', function (Blueprint $table) {
            $table->string('slug')->nullable()->unique()->after('name');
            $table->string('image')->nullable()->after('stock');
        });
    }

    public function down(): void
    {
        Schema::table('products', function (Blueprint $table) {
            $table->dropUnique(['slug']);
            $table->dropColumn(['slug', 'image']);
        });
    }
};
```

Jalankan migration, lalu buat symlink supaya file di `storage/app/public` bisa diakses dari browser lewat `/storage/...`:

```bash
php artisan migrate
php artisan storage:link
```

> **Penting:** index `unique` adalah pengaman terakhir. Service yang membuat slug unik, tetapi kalau ada bug atau dua request masuk bersamaan, database tetap menolak slug ganda.

## Langkah 5 — Kembangkan ProductService

Ini inti pelajarannya. Kita ubah tiga method dan menambah dua method `private`.

**Slug unik.** `Str::slug()` mengubah "Kopi Susu" menjadi `kopi-susu`. Kalau slug itu sudah dipakai produk lain, tambahkan angka di belakang sampai ketemu yang kosong. Saat update, produk yang sedang diedit dikecualikan dengan `whereKeyNot()`, supaya produk tidak "bentrok dengan dirinya sendiri".

```php
private function generateUniqueSlug(string $name, ?int $ignoreId = null): string
{
    $base = Str::slug($name);
    $slug = $base;
    $counter = 2;

    while (
        Product::where('slug', $slug)
            ->when($ignoreId !== null, fn ($query) => $query->whereKeyNot($ignoreId))
            ->exists()
    ) {
        $slug = "{$base}-{$counter}";
        $counter++;
    }

    return $slug;
}
```

**Gambar.** `$image->store('products', 'public')` menyimpan file ke `storage/app/public/products` dengan nama acak yang unik, lalu mengembalikan path-nya (misalnya `products/abc123.jpg`). Path inilah yang disimpan di kolom `image`.

**Urutan saat update dan delete itu penting.** Database dan file system adalah dua tempat berbeda, dan transaksi database **tidak** bisa membatalkan operasi file. Jadi aturannya: ubah database dulu, hapus file lama **setelah** database berhasil. Kalau urutannya dibalik dan query gagal, gambar sudah terhapus padahal datanya masih menunjuk ke file itu.

Karena setiap method hanya menjalankan satu query tulis (`create` atau `update` atau `delete`), kita tidak perlu `DB::transaction()` di sini. Transaksi baru berguna kalau satu aksi menulis ke beberapa tabel sekaligus, seperti yang dibahas di pelajaran 04.

Here's your complete `app/Services/ProductService.php`:

```php title="app/Services/ProductService.php"
<?php

namespace App\Services;

use App\Models\Product;
use Illuminate\Contracts\Pagination\LengthAwarePaginator;
use Illuminate\Http\UploadedFile;
use Illuminate\Support\Facades\Storage;
use Illuminate\Support\Str;

class ProductService
{
    public function paginate(): LengthAwarePaginator
    {
        return Product::latest()->paginate(10);
    }

    /**
     * @param  array<string, mixed>  $data
     */
    public function create(array $data, ?UploadedFile $image = null): Product
    {
        $data['slug'] = $this->generateUniqueSlug($data['name']);

        if ($image !== null) {
            $data['image'] = $image->store('products', 'public');
        }

        return Product::create($data);
    }

    /**
     * @param  array<string, mixed>  $data
     */
    public function update(Product $product, array $data, ?UploadedFile $image = null): void
    {
        $oldImage = $product->image;

        if ($data['name'] !== $product->name || $product->slug === null) {
            $data['slug'] = $this->generateUniqueSlug($data['name'], $product->id);
        }

        if ($image !== null) {
            $data['image'] = $image->store('products', 'public');
        }

        $product->update($data);

        if ($image !== null) {
            $this->deleteImage($oldImage);
        }
    }

    public function delete(Product $product): void
    {
        $image = $product->image;

        $product->delete();

        $this->deleteImage($image);
    }

    private function generateUniqueSlug(string $name, ?int $ignoreId = null): string
    {
        $base = Str::slug($name);
        $slug = $base;
        $counter = 2;

        while (
            Product::where('slug', $slug)
                ->when($ignoreId !== null, fn ($query) => $query->whereKeyNot($ignoreId))
                ->exists()
        ) {
            $slug = "{$base}-{$counter}";
            $counter++;
        }

        return $slug;
    }

    private function deleteImage(?string $path): void
    {
        if ($path !== null) {
            Storage::disk('public')->delete($path);
        }
    }
}
```

Perhatikan `$product->slug === null` di `update()`: inilah yang memberi slug pada produk lama (dibuat sebelum migration Langkah 2) begitu produk itu diedit.

## Langkah 6 — Controller: pisahkan data teks dan file

Controller hanya berubah di `store()` dan `update()`. `$request->safe()->except('image')` mengambil data yang lolos validasi **tanpa** field `image`, karena file dikirim terpisah lewat `$request->file('image')`. Kalau pengguna tidak memilih file, `file('image')` bernilai `null` dan service melewati bagian gambar.

```php
// sebelum
$this->products->create($request->validated());

// sesudah
$this->products->create(
    $request->safe()->except('image'),
    $request->file('image'),
);
```

### Final Complete Controller

Here's your complete `app/Http/Controllers/ProductController.php`:

```php title="app/Http/Controllers/ProductController.php"
<?php

namespace App\Http\Controllers;

use App\Http\Requests\StoreProductRequest;
use App\Http\Requests\UpdateProductRequest;
use App\Models\Product;
use App\Services\ProductService;
use Illuminate\Http\RedirectResponse;
use Illuminate\View\View;

class ProductController extends Controller
{
    public function __construct(
        protected ProductService $products,
    ) {}

    public function index(): View
    {
        $products = $this->products->paginate();

        return view('products.index', compact('products'));
    }

    public function create(): View
    {
        return view('products.create');
    }

    public function store(StoreProductRequest $request): RedirectResponse
    {
        $this->products->create(
            $request->safe()->except('image'),
            $request->file('image'),
        );

        return to_route('products.index')
            ->with('success', 'Produk berhasil ditambahkan.');
    }

    public function show(Product $product): View
    {
        return view('products.show', compact('product'));
    }

    public function edit(Product $product): View
    {
        return view('products.edit', compact('product'));
    }

    public function update(UpdateProductRequest $request, Product $product): RedirectResponse
    {
        $this->products->update(
            $product,
            $request->safe()->except('image'),
            $request->file('image'),
        );

        return to_route('products.index')
            ->with('success', 'Produk berhasil diperbarui.');
    }

    public function destroy(Product $product): RedirectResponse
    {
        $this->products->delete($product);

        return to_route('products.index')
            ->with('success', 'Produk berhasil dihapus.');
    }
}
```

Bandingkan dengan godaan menulis semuanya di controller: slug, `store()`, dan `Storage::delete()` akan tersebar di `store()`, `update()`, dan `destroy()`. Di sini controller tidak tahu apa pun soal slug atau lokasi file.

## Langkah 8 — Tes slug dan gambar

Inilah keuntungan terbesar service: aturan slug dan gambar bisa dites langsung tanpa membuka browser atau mengirim request HTTP. `Storage::fake('public')` mengganti disk `public` dengan disk sementara, jadi tes tidak mengotori folder `storage` sungguhan. `UploadedFile::fake()->image()` membuat file gambar palsu.

```bash
php artisan make:test ProductSlugImageTest
```

Here's your complete `tests/Feature/ProductSlugImageTest.php`:

```php title="tests/Feature/ProductSlugImageTest.php"
<?php

namespace Tests\Feature;

use App\Models\Product;
use App\Services\ProductService;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Http\UploadedFile;
use Illuminate\Support\Facades\Storage;
use Tests\TestCase;

class ProductSlugImageTest extends TestCase
{
    use RefreshDatabase;

    protected function setUp(): void
    {
        parent::setUp();

        Storage::fake('public');
    }

    private function dataProduk(array $attributes = []): array
    {
        return array_merge([
            'name' => 'Kopi Susu',
```

## Error yang sering muncul

| Gejala | Penyebab | Solusi |
|---|---|---|
| `$request->file('image')` selalu `null` | Form tidak memakai `enctype="multipart/form-data"` | Tambahkan atribut itu di tag `<form>` |
| Gambar tersimpan tetapi browser menampilkan 404 | Symlink `public/storage` belum dibuat | Jalankan `php artisan storage:link` |
| Kolom `slug` dan `image` di database tetap kosong | Belum ditambahkan ke `$fillable` | Tambahkan `'slug'` dan `'image'` di model |
| `Cannot add a NOT NULL column with default value NULL` | Kolom `slug` dibuat wajib di tabel yang sudah berisi data | Pakai `nullable()` seperti di Langkah 2 |
| `UNIQUE constraint failed: products.slug` | Slug dibuat di luar service (misalnya langsung `Product::create()` dengan slug manual) | Selalu buat produk lewat `ProductService` |
| `GD extension is not installed` saat tes | `UploadedFile::fake()->image()` butuh ekstensi GD | Aktifkan `extension=gd` di `php.ini` |
